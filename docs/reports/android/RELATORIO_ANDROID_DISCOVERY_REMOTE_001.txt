## 3. Implementação

- Stack única: Retrofit 2.11.0, OkHttp 4.12.0, Kotlin Serialization 1.7.3 e MockWebServer 4.12.0.
- Versões centralizadas no version catalog; AGP, Kotlin, Compose, Hilt e SDK não foram actualizados.
- DiscoveryApi contém apenas Home, Search e Detail plurais.
- DTOs reproduzem a resposta canónica: merchantId, availability string, fulfillmentOptions, distanceMeters, rating, popularityScore, featured, catalogAvailable e detalhe opcional.
- AndroidPublicErrorEnvelope é desserializado pelo code canónico.
- Mappers puros mantêm UNKNOWN, ignoram fulfillment futuro e não fabricam categoria, rating, popularidade, horário, endereço ou media.
- RemoteDiscoveryRepository mapeia INVALID_REQUEST, SORT_NOT_SUPPORTED, CAPABILITY_NOT_SUPPORTED, MERCHANT_NOT_FOUND, RATE_LIMITED, 503, timeout, rede e contrato.
- CancellationException é sempre relançada.
- DiscoveryPagingMapper centraliza Android 1-based e backend 0-based.
- SelectableDiscoveryRepository não contém fallback Remote para Mock.
- Source selector é central, injectado e observável; ViewModels dependem apenas de DiscoveryRepository.
- Hilt separa repository, source policy e rede sem expor Retrofit à UI.
- catalogAvailable vem exclusivamente do backend; nenhuma Catalog API foi criada.
- O cliente não envia Authorization nem X-Tenant-Id, X-Tenant-Code ou X-Business-Id.
- Cache persistente não foi criado. Sem cache local validado, um 304 não acompanhado de representação é ContractError; o cliente não inventa body.

- pageSize: default 20, máximo 100.
