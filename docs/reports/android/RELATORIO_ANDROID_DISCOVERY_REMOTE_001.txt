## 3. Implementação realizada

- Stack única: Retrofit 2.11.0, OkHttp 4.12.0, Kotlin Serialization 1.7.3 e MockWebServer 4.12.0.
- Versões centralizadas em gradle/libs.versions.toml; SDK, AGP, Gradle, Kotlin, Compose e Hilt não foram actualizados.
- Permissão INTERNET adicionada.
- Network factory central com JSON estrito, ignoreUnknownKeys, timeouts explícitos, sem retry automático e sem HTTP body logging.
- DiscoveryApi cobre apenas os três GETs Discovery.
- DTOs separados de domínio/UI para Home, Search, Merchant, resumo, paginação, disponibilidade, fulfillment, dinheiro e erro.
- DiscoveryDtoMapper executa DTO -> Domain, trata nulls/listas vazias, UNKNOWN, fulfillment futuro, catalogAvailable e horário.
- DiscoveryPagingMapper centraliza Android 1-based <-> backend 0-based e rejeita valores inválidos.
- RemoteDiscoveryRepository mantém Retrofit fora de ViewModels/composables e nunca recorre a fixtures em falha.
- SelectableDiscoveryRepository escolhe a fonte apenas pela política explícita de ambiente/desenvolvimento.
- Hilt foi separado em módulos de repository, source policy e rede para permitir doubles instrumentados sem bindings ambíguos.
- MerchantSummary passou a preservar catalogAvailable vindo da fonte; Merchant Overview continua a controlar a navegação para Catalog sem implementar Catalog Remote.
- Search recebeu paginação incremental/Load More e mantém resultados ao atingir fim de lista.
- Home com query usa o endpoint Search, pois Home remoto não aceita query; nenhum parâmetro inexistente é enviado.

Arquitectura Android auditada:
1. Discovery estava integralmente em modo Mock.
2. DiscoveryRepository já era uma abstracção pronta para Remote.
3. Antes desta fase não havia separação/select explícito; agora Mock, Remote e selector estão separados.
4. Antes todos os ambientes usavam InMemory; agora Debug inicia Mock seleccionável e Staging/Release usam Remote fixo.
5. ViewModels, UiStates, UiModels, rotas, navegação e a maioria dos modelos de domínio foram preservados.
6. Campos remotos mapeados explicitamente: categorias, secções, paginação, availability, fulfillment, rating, dinheiro, promoção, detalhe e catalogAvailable.
7. Dívida não bloqueante de implementação: não existe URL/deployment Staging Discovery. Dívida bloqueante de integração real: backend Discovery não está integrado/deployado.

## 4. Política Mock e Remote

- Debug: DISCOVERY_SOURCE=MOCK, selector visível nas ferramentas de desenvolvimento, Remote seleccionável explicitamente e base URL configurável por DISCOVERY_DEBUG_BASE_URL.
- Staging: DISCOVERY_SOURCE=REMOTE fixo, selector desactivado, URL configurável por DISCOVERY_STAGING_BASE_URL, cleartext bloqueado.
- Release: DISCOVERY_SOURCE=REMOTE fixo, selector desactivado, URL configurável por DISCOVERY_RELEASE_BASE_URL, HTTPS validado em runtime, cleartext bloqueado.
- URL ausente produz ContractError; não foi inventado domínio ou IP.
- Não existe fallback Remote -> Mock.
- Mock permanece para previews, testes e desenvolvimento isolado explicitamente seleccionado.

## 5. Paginação, sort e filtros

- Android 1 -> backend 0; Android N -> N-1; backend 0 -> Android 1.
- Search envia page/pageSize via mapper central; próxima página agrega resultados e fim vazio preserva os já apresentados.
- Remote anuncia somente NAME e a UI remove os restantes sorts.
- Remote não apresenta/envia onlyOpen nem fulfillment filter.
- Solicitação programática de sort/filtro remoto não suportado termina em UnsupportedSort/InvalidRequest antes da rede.
- Mock preserva FEATURED, NAME, NEAREST, TOP_RATED, MOST_POPULAR, onlyOpen e fulfillment.

## 6. Erros e resiliência

- HTTP 400 INVALID_REQUEST -> InvalidRequest.
- HTTP 400 SORT_NOT_SUPPORTED -> UnsupportedSort.
- HTTP 401 -> Unauthorized.
- HTTP 403 -> Forbidden.
- HTTP 404 -> NotFound.
- HTTP 429 -> RateLimited.
- HTTP 503 -> ServiceUnavailable.
- Outros 5xx -> Server.
- IOException -> NetworkUnavailable.
- SocketTimeoutException -> Timeout.
- JSON incompatível, body ausente, configuração ausente ou mapping inválido -> ContractError.
- CancellationException é relançada.
- Retry repete a request actual; não troca a fonte de dados.
